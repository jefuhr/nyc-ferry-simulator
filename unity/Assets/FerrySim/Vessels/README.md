# Ferry models

The original Blender generator and rebuild instructions are in `art/blender/README.md`.
`Models/` contains the native FBX exports, palette and export receipts; `Materials/` and
`Resources/FerrySimVessels/<class>/LOD*.prefab` are generated by `FerryModelImporter.Build`.
The runtime assembly references no other simulator assembly and performs no per-frame work.
The editor author maps materials by their FBX names because native import may reorder submeshes.
It validates every mount before removing unit-conversion float noise against the shared source formulas.
Glazing keeps its authored outward winding; its back face does not block the bridge camera.

`VesselGreybox` draws the authored LOD0 by default. Its serialized `useGreybox` switch
(and `UseGreybox` property) selects the retained procedural fallback. A missing/unsupported
model also keeps the greybox visible. The hidden greybox remains available for existing
geometry tests; it never gains physics authority. Run changes replace both visuals.

`TrafficView` uses the shared LOD1 prefab only when the MMSI is an explicitly audited
T/K identity. Length and beam scale independently to the existing
`TrafficHullSize`; class vertical proportions remain unchanged because AIS draft does not
establish cabin/freeboard height. Each instance shares the imported mesh and material.
Other traffic uses its existing greybox. No new code runs in `TrafficView.Place`.

Navigation-light configuration reads the active model's named transforms once, including
independent port and starboard mounts. Model-free vessels use the existing generic/greybox
layout. All own-vessel light positions match the previous layout within 1 mm; light sectors,
intensities, status and switching rules are unchanged. `Atmosphere` resolves the model on
run start before reading mounts so subscriber order cannot retain another class's layout.

The FBX has no colliders. The core contact outline, frame conversion, simulation, input,
recording and camera code are unchanged. The hollow wheelhouse has outward-facing glazing
so the bridge camera can see down onto the foredeck without looking through an opaque cabin.

Tests under `Tests/EditMode` guard import axes/scale, mounts, triangle/material budgets and
identity selection. `Tests/PlayMode` exercises both classes in the integrated slice, the
fallback switch, lighting, real AIS traffic mesh sharing, and day/night captures. Evidence
and scene draw counts go to `artifacts/ferry-models/`. Each count covers one explicit
1600x1000 camera render, with automatic rendering disabled and counters read after the next
frame boundary; world geometry, labels and URP passes are included. Editor counts are not a GPU
benchmark or a physical-device acceptance claim. Existing traffic/E2E frame and allocation
budgets remain the performance gate.

At base `d769106`, the traffic producer marks only literal `T`/`K` audit rows as `FerryCandidate`,
whereas its two audited K rows use `K-IC18130`. Model selection therefore reads the audited
MMSI mapping directly, including those K rows; it does not alter the traffic pack, leave-out
logic, or the meaning of the existing candidate flag.
