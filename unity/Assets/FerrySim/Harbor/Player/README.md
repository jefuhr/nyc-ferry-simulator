# Harbor Player

`HarborPlayerSmokeRun` owns `-ferrysim-smoke` for a harbor-first player. It starts Astoria on a real environment/traffic day through the scene's existing catalog and launcher, waits for real tileset readiness, drives astern, waits for the shared chart pack load, opens the chartplotter and the radar in the wheelhouse and requires them to draw real content (at least 200 echo bins in the radar picture, chart vertices in the plotter's static canvas and a drawn target) before capturing them to `smoke-displays.png`, then captures both views, closes the recording and writes an explicit verdict. The `harbor` object of `smoke.json` adds the chart's state, digests, load/index/tessellation times, the seconds from composition to the displays' connection, the drawn counts, the displays screenshot path and the process memory the player can read; the two-screenshot report shape `release.sh` reads is unchanged. `harbor.memory` holds `Profiler.GetMonoUsedSizeLong`, `GetMonoHeapSizeLong`, `GetTotalAllocatedMemoryLong`, `GetTotalReservedMemoryLong` and the process working set at `composed` (services connected, chart loading), `run_started`, `scene_ready` (the tiles), `chart_ready` (the frame the displays connected to the ready chart, wherever it falls), `after_drive`, `displays_shown` and `end`, plus the per-frame `peak` of the four Profiler figures. `-ferrysim-smoke-no-displays` leaves both displays off for the comparison run `release.sh` makes beside the ordinary one (`smoke/result-no-displays/`); the script samples each player's resident set about once a second (`rss-samples.csv`, `rss-peak-bytes.txt`). It requires packaged paths and unavailable repository fallback data. The reported maximum speed is sampled at rendered-frame polls; the legacy scalar drawn-water field is omitted because it is not measured for the spatial harbor surface.

The two materials in `Resources/` retain `FerrySim/SolidColour` and `FerrySim/HarborLabel`. Navigation creates its own materials through `Shader.Find`; these small source assets give the player explicit shader dependencies without changing the runtime navigation owner, scene or project settings. The signal-light shader already has its own existing Resources dependency, and traffic's URP Lit shader is retained by the vessel materials.

The player and test folders have their own assemblies. EditMode tests cover first-scene selection, installed path containment and a calibrated zero-allocation polling predicate. Build-area tests cover the retained shader dependencies and the approved folder-resolution regression. Installed-player smoke, screenshots and Windows follow-up commands are described in `docs/releasing.md` and the task report.
