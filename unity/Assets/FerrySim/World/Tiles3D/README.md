# Tiles3D probe

Owner: **world3d-tiles**. This is the Windows probe that [decision 0004](../../../../../docs/decisions/0004-harbor-world-local-3d-tiles.md) asks for. It is a small development player that loads the harbor's local 3D Tiles over `file://` from its StreamingAssets with Cesium for Unity 1.26.0, flies a short path, and writes what happened to `probe.json`. It is a probe only: harbor-world builds the harbor scene, its terrain shader and the real packaging.

| Path | Assembly | What |
|---|---|---|
| `Runtime/` | `FerrySim.World.Tiles3D` | `TilesetProbe` (the run), `ProbeReport` (probe.json and its verdict), `ProbeOptions` (command line), `ProbePath` (the flight), `TilesetUrl` (file:// URLs), `TilesetPayloadManifest` (payload.json), `Tiles3DProbe.shader` |
| `Editor/` | `FerrySim.World.Tiles3D.Editor` (Editor only) | `ProbeSceneBuilder` (writes the scene), `ProbePlayerBuild` (the player builds), `TilesetPayload` (copies the tiles in) |
| `Scenes/Tiles3DProbe.unity` | | generated by `ProbeSceneBuilder`; never hand-edited |
| `Tests/EditMode/` | `FerrySim.World.Tiles3D.Tests.EditMode` | the copy step, the verdict, URLs, options, the flight and the scene |

## The scene

- A `CesiumGeoreference` sits at the shared world origin (40.7000, -74.0150, ellipsoidal height 0), scale 1.
- Under it is the harbor `Cesium3DTileset`, disabled and with an empty URL.
  - It is set to load from a URL, not from Cesium ion, and carries no token.
  - Physics meshes are off, and the tile cache is capped at 256 MiB (`maximumCachedBytes`, against Cesium's default 512 MB).
- The main camera has a `CesiumGlobeAnchor` and `CesiumOriginShift` at 100 m, as in the slice.
- A directional sun and flat ambient light complete it, with the `TilesetProbe` that drives the run.
- Rebuild it with **FerrySim > World > Tiles3D > Rebuild Probe Scene**, or `-executeMethod FerrySim.World.Tiles3D.EditorTools.ProbeSceneBuilder.BuildFromCommandLine`.

## The run

At start the probe works through these steps:

1. Checks every packaged file against `StreamingAssets/harbor3d/payload.json` (size and SHA-256).
2. Builds the tileset's URL from the absolute path of `StreamingAssets/harbor3d/tileset.json`, every segment escaped and the drive letter kept (`file:///C:/...`). It records System.Uri's form of the same path beside it.
3. Sets the URL, then enables the tileset.
4. Waits until Cesium's load progress has read 100% for 10 frames with at least one tile loaded, or 60 s.
5. Takes `probe-start.png`.
6. Flies 40 s, from low over the Upper Bay, past Wall St/Pier 11 and the Brooklyn and Williamsburg bridges, to 600 m over Hunters Point, looking across the harbor.
7. Waits again, with Cesium's selection statistics on, and takes `probe-end.png`.
8. Writes `probe.json` and quits: exit code 0 when it passed, 1 when it failed, 2 for an unusable command line.

`probe.json` goes beside the executable (the folder holding the .exe, or the folder holding the .app), or into the folder `-probe-out <folder>` names. It has:
- tiles requested, loaded and failed, the loaded count per level, and a few of the URLs Cesium created tiles from (they show how it resolved the relative ones);
- Cesium's errors and tileset load failures;
- load times;
- frame-time percentiles during the flight;
- Unity's System Used Memory (the process footprint, cesium-native included) and the OS resident set where the runtime can read it.

"Requested" is the tiles loaded, plus those failed, plus those still queued when the run ended.

The probe fails on any of these:
- no tile loaded;
- any tile or tileset load failure;
- any error or warning from Cesium, or any error at all;
- a view not loaded within 60 s;
- a missing or changed packaged file;
- a screenshot with 50 colours or fewer (nothing drawn);
- a URL that isn't a local `file:///` one.

## Building it

Build the pipeline's tiles first (`data-pipeline/ferrydata/world3d/README.md`). The player build reads the build settings' enabled scenes for `PlayerPayloadBuildStep`, as every standalone build does. So the slice outputs must exist too: `ferrydata build --slice lower-east-river`, `export-unity` and the environment packs. The probe player carries them (about 25 MB, unused), with `build-info.json`, whose commit the probe reports.

```sh
UNITY=/Applications/Unity/Hub/Editor/6000.3.27f1/Unity.app/Contents/MacOS/Unity
lockf -k "$HOME/FerrySim-cache/heavy.lock" lockf -k "$HOME/FerrySim-cache/unity.lock" "$UNITY" -batchmode -projectPath "$PWD/unity" -buildTarget Win64 \
  -executeMethod FerrySim.World.Tiles3D.EditorTools.ProbePlayerBuild.BuildWindowsFromCommandLine -logFile "$PWD/artifacts/tiles3d-probe/windows-build.log"
lockf -k "$HOME/FerrySim-cache/heavy.lock" lockf -k "$HOME/FerrySim-cache/unity.lock" "$UNITY" -batchmode -projectPath "$PWD/unity" -buildTarget OSXUniversal \
  -executeMethod FerrySim.World.Tiles3D.EditorTools.ProbePlayerBuild.BuildMacFromCommandLine -logFile "$PWD/artifacts/tiles3d-probe/mac-build.log"
```

- **Outputs.**
  - Windows: an x64 development player in `artifacts/tiles3d-probe/windows/FerrySim Tiles3D Probe/` (the spaces are on purpose: the URL has to survive them), zipped as `FerrySim-Tiles3D-Probe-windows-x64.zip` without Burst's DoNotShip folders.
  - Mac: an Apple silicon `Tiles3DProbe.app` in `artifacts/tiles3d-probe/mac/`, signed ad hoc again after the tiles go in.
  - Each build writes `probe-build.json` beside the player: the scope and why, the tiles, the payload's size, and the zip's size and SHA-256.
- **Options.** `-probeOutput <absolute folder>`, `-probeTiles <folder>` and `-probeScope auto|full|slice`.
- **Scope.** The whole harbor goes into `StreamingAssets/harbor3d/`, unless the Windows zip would exceed 400 MB. In that case the build carries the slice's tiles and their eight neighbours, with the root tileset rewritten to name only them. `payload.json` and `probe-build.json` say which.
- **Checks.** Every file is checked against the pipeline's `index.json` before it is copied, so a player never carries tiles the pipeline didn't write.

## Running it on a Mac

The binary inside the .app carries the project's product name, not the .app's:

```sh
mkdir -p artifacts/tiles3d-probe/mac-run
lockf -k "$HOME/FerrySim-cache/heavy.lock" lockf -k "$HOME/FerrySim-cache/unity.lock" \
  "artifacts/tiles3d-probe/mac/Tiles3DProbe.app/Contents/MacOS/NYC Ferry Simulator" -probe-out "$PWD/artifacts/tiles3d-probe/mac-run" \
  -screen-fullscreen 0 -screen-width 1280 -screen-height 720 -logFile "$PWD/artifacts/tiles3d-probe/mac-run/Player.log"
```

The Windows steps for the user's PC are in the task report.
