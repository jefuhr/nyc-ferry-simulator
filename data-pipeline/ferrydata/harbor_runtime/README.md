# Harbor runtime export (proposed wave 3b contract)

This offline Python export turns the existing harbor working products into resident navigation/query data. It never reads render GLBs, fetches data, changes the slice, changes contact eligibility, or creates new physical collision geometry. The coordinator must review this schema before freezing wave 3b C# DTOs.

From the repository root:

```sh
lockf -k "$HOME/FerrySim-cache/heavy.lock" env PYTHONPATH=data-pipeline uv run --project data-pipeline python -m ferrydata.harbor_runtime build
PYTHONPATH=data-pipeline uv run --project data-pipeline python -m ferrydata.harbor_runtime verify --harbor data/processed/harbor
uv run --project data-pipeline pytest data-pipeline/tests/harbor_runtime -q
```

`--harbor` chooses the input root and `--out` chooses the runtime root. The default output is `data/processed/harbor/runtime/`. An output inside the input tree must be exactly `runtime/`; ancestors and existing output directories containing unowned files are refused. All derivation and verification happens in a temporary sibling directory before replacing output files. Publication is intended for offline build tooling, not concurrent readers: the individual file copies are not a whole-directory atomic switch.

## Frames, identity and provenance

Positions/geometry are world horizontal NED **[north_m, east_m]**, through the shared WGS84 origin **[40.7000, -74.0150]**. These JSON geometry objects are explicitly named `geometry_ne_m`; despite their Polygon/LineString nesting they are **not WGS84 GeoJSON**. Do not feed them directly to a longitude/latitude API. Polygon normalization fixes ring starts and component/hole order for repeatable bytes. Barge polygons in both `landings.json` and `footprints.json` additionally orient exteriors counterclockwise in **[north, east]** axes (clockwise viewed from above in east/north), with holes opposite: solid stays on the right and the core water normal `(deltaEast, -deltaNorth)` points out of solid. `canonical(..., solid_right=True)` normalizes before orienting, including after footprint clipping, so re-canonicalization preserves that rule. Verification checks every barge ring in both payloads.

Other semantic outlines (shoreline, structures, bridge spans/piers and coverage) promise canonical geometry ordering only, with no contact/water-side orientation contract. They may be lines or points, and readers must not infer contact normals from them. The copied `contacts.json` retains its source's contact orientation and authority unchanged. Source vertices retain the pipeline's millimetre precision; overlapping tile fragments merge by source ID. Query geometries clip to the union of active tile squares and preserve polygon holes and line/point forms. No buffer invents polygon widths for charted lines.

ENC identities use `enc:<LNAM>`. Physical bridge identities use `bridge:<smallest member LNAM>` from the existing clearance audit. This is stable for identical source membership; a new smaller member can change a group's identity, so future source-refresh migration may require an explicit alias table. Berth IDs combine stop ID, physical structure ID and reviewed berth order. Stop order is the existing harbor index order, berth order is the source `berth_order`, and arrays with no source ordering sort by stable ID. No timestamps or absolute workstation paths enter output bytes.

| File | Layout and meaning |
|---|---|
| `aids.json` | `ferrysim-harbor-aids/1`; `aids[]` has `id`, `source_id`, `position_ne_m`, `position_lonlat`, and all non-position ENC `properties`, including every light-character field. Exact seam duplicates collapse, conflicting duplicates fail. Includes candidates in source tile margins, as in the chart export. |
| `bridges.json` | `ferrysim-harbor-bridges/1`; `bridges[]` has physical IDs/names, complete audit evidence, and source-ID `spans[]`. Each span retains its own geometry and all source clearance/property variants. Unknown clearances never inherit from another span. `piers[]` includes only charted SLCONS category 4/5 pier features geometrically intersecting a span, with per-span intersection evidence. This is a geometric association, not surveyed structural attachment; `pier_inventory_complete=false` explicitly leaves other membership unknown. |
| `contacts.json` | Exact original `unity/contacts.json` bytes, including v2 fields, evidence and optional berth metadata. The existing reader/gate remains the contact authority. |
| `landings.json` | `ferrysim-harbor-landings/1`; `stops[]` preserves index identities/names/order and contains ordered `berths[]` with every source `berth_*` field and `primary_face`. `barges[]` is unique by physical `structure_id`, with a closed Polygon and source/confidence per polyline. All landing/back-side source polylines are polygonized together, including gate-ineligible sides; incomplete outlines fail instead of guessing a closing edge. Multiple berths reference one barge. |
| `geoid.json` | `ferrysim-harbor-geoid/1`; one 250 m lattice, world origin, shape, byte layout and explicit active-cell mask. Values mean ellipsoidal height of NAVD88 zero, in metres; add them to NAVD88 elevation. |
| `geoid.f64` | Little-endian float64 `[rows, cols]`, row-major, rows increasing north, columns increasing east. Each node is sampled once from the existing world3d geoid owner rule. Bilinear interpolation uses these shared nodes and is continuous across tile edges. Unused nodes store zero and must never be sampled through masked cells. |
| `geoid_cells.u8` | `[rows-1, cols-1]` bytes; 1 = active cell, 0 = outside/coverage hole. No extrapolation. `geometry.sample_geoid` is the scalar reference, including outer-edge and inactive-hole behavior. |
| `footprints.json` | `ferrysim-harbor-queries/1`; union coverage and stable resident `footprints[]`, with semantic `shoreline`, `structure`, `bridge`, or `barge`; source IDs, normalized geometry, unknown vertical bounds, and `collision_authority=false`. ENC land areas supply shoreline; chart constructions supply structures; bridges and barges retain their separate identity. These categories can overlap physically, so readers combine semantic hits rather than treating every record as another collision. |
| `manifest.json` | `ferrysim-harbor-runtime/1`; origin, counts, source raw-byte hashes, depth digest linkage and every payload file SHA-256. `schema_status` identifies the proposal. |
| `DIGEST` | SHA-256 lowercase hex plus LF. Hash raw `manifest.json` bytes first, then the eight payloads in `pack.FILES` order: UTF-8 relative filename, NUL, raw bytes, NUL for each. Same framing as env/traffic packs. Manifest whitespace changes invalidate the digest. |

`verify` checks the exact inventory, raw digest, individual hashes and structural consistency. Geoid validation requires the supported format, little-endian float64 dtype and row-major layout, integer `rows`/`cols` of at least 2 (booleans/floats are refused), and integer `mask_shape == [rows-1, cols-1]`; the mask is uint8 by its fixed `geoid_cells.u8` schema. Consistent hashes cannot bypass these reader requirements. `verify --harbor ...` additionally checks source hashes against the current input files. Build checks tile output pins, shared source pins in the 3dtiles index, every depth grid hash and the full environment depth digest before deriving data. Integrity hashes detect corruption; they are not authenticity signatures.

## Unknowns and wave 3b review

- **Vertical bounds are `[null, null]`.** ENC land/construction footprints have no complete height model; line-only sources also lack width. Radar cannot infer top heights, reflection strength/RCS, sensor visibility, material penetration or occlusion at a given altitude from these alone. Chartplotter can use plan geometry, semantic IDs and source properties without pretending those unknowns are known.
- **Bridge underside NAVD88 remains null.** Original MHW clearance and its source note are preserved. The current harbor inputs do not assign a span-specific MHW-to-NAVD88 conversion. Converting via an arbitrarily selected tide gauge would invent a datum relationship. Tower/deck extents and actual bridge navigation-light positions remain unknown.
- **Floating barge bounds need runtime tide and an approved vertical extent.** Geometry/provenance does not make a stop/berth a safe runnable start. Crew restrictions and refused contacts remain in the copied source.
- **Geoid spacing and parity require review.** One 250 m lattice is continuous, unlike switching overlapping tile interpolants. It is not guaranteed equal to the terrain at intermediate points. The task report measures differences at every landing and shared seams against existing world3d ownership and the slice geoid where applicable. The source NAD83(2011)/GRS80-to-WGS84 approximation remains unchanged; it is documented in `geoid.json`.
- **No skyline contract is frozen here.** A separate future semantic pack can use the same frame, source IDs, nullable vertical bounds and integrity framing. Render layers/cache limits/materials belong to scene configuration, not this view-independent dataset; terrain data does not change when building sources change.
- **Spatial indexing is a reader decision.** The compact source-keyed arrays are independent of view/renderer residency. Wave 3b should construct deterministic resident spatial indices once at load time; this export contains no transient render tile IDs or Unity proxies.
